EasyKids Robot Soccer — HTML / CSS / JavaScript ธรรมดา
=======================================================

เวอร์ชันพร้อมใช้งาน 2026-08-19 (stable3-pause-fix)

ไฟล์หลัก
- index.html            หน้าควบคุมของกรรมการ
- display.html          หน้าจอแสดงเวลาและคะแนน
- css/styles.css        รูปแบบและธีมทั้งหมด
- js/firebase-config.js ตั้งค่า Firebase
- js/control.js         ระบบหน้าควบคุม
- js/display.js         ระบบหน้าจอแสดงผล

วิธีใช้งาน
1. เปิดโฟลเดอร์นี้ด้วย VS Code แล้วใช้ Live Server เปิด index.html
2. กรอกรหัสสนาม 4 หลัก และรหัสผ่านห้อง 2877
3. เปิด display.html ในอีกหน้าจอ แล้วกรอกรหัสสนามและรหัสผ่านเดียวกัน
4. ตั้งเวลา ชื่อทีม และควบคุมคะแนนจาก index.html

สำคัญ: อย่าย้ายไฟล์ออกจากโครงสร้างโฟลเดอร์ เพราะหน้าเว็บอ้างอิงไฟล์ใน
css/, js/, logos/ และ sounds/ หากยังไม่มีโลโก้หรือเสียง ระบบหลักยังทำงานได้
แต่รูป/เสียงส่วนนั้นจะไม่แสดง

ประวัติการแข่งขัน
- เมื่อหมดเวลา นาฬิกาจะหยุดที่ 00:00.000 แต่ยังไม่จบและไม่บันทึกแมตช์
- ระบบบันทึกประวัติเฉพาะเมื่อกรรมการกดจบการแข่งขัน
- ข้อมูลอยู่ที่ rooms/{roomCode}/history ใน Firebase Realtime Database
- แต่ละแมตช์ใช้ Firebase Push ID ไม่ซ้ำกันและแสดงประวัติทุก child ตามเวลาจบ
- ลบได้ทีละแมตช์หรือล้างประวัติทั้งหมดจากหน้าควบคุม
- เวอร์ชันนี้ใช้ Firebase listener โดยตรง ไม่อ่าน REST ซ้ำ จึงไม่เกิดข้อมูลเก่า
  ย้อนมาทับรายการล่าสุด และใช้ ID เดียวกันตั้งแต่เริ่มจนบันทึกจบแมตช์

ไม่ต้องติดตั้ง Node.js, npm, React หรือ Framework ใด ๆ
สามารถอัปโหลดโฟลเดอร์ทั้งหมดขึ้น Static Hosting ได้ทันที

ไฟล์โลโก้และเสียง
- logos/logo-left.png
- logos/logo-right.png
- sounds/countdown.mp3
- sounds/whistle.mp3
- หากยังไม่มีไฟล์เสียง ระบบจะสร้างเสียงนับถอยหลังและนกหวีดสำรองให้อัตโนมัติ

Firebase
- เปิด Realtime Database ในโปรเจกต์ easykidssoccer
- เลือก Region: Singapore (asia-southeast1)
- นำ Rules จาก firebase-rules.json ไปวางในหน้า Rules
- กด Publish Rules ก่อนทดลองใช้งานเวอร์ชันนี้
- ถ้า URL ฐานข้อมูลไม่ตรง ให้แก้ databaseURL ใน js/firebase-config.js

รายการที่ตรวจและปรับปรุงใน stable1
- แก้ประวัติแสดงเพียง 1 รายการ และรองรับข้อมูลประวัติรูปแบบเก่า
- ป้องกันการบันทึกประวัติซ้ำเมื่อมีหน้าควบคุมมากกว่าหนึ่งเครื่อง
- เริ่ม/พัก/เดินเวลาต่อด้วย transaction ลดสถานะชนกันระหว่างหลายอุปกรณ์
- จำกัดเวลา 00:01–99:59, คะแนน 0–999 และชื่อทีมไม่เกิน 30 ตัวอักษร
- แจ้งสถานะออฟไลน์/ข้อผิดพลาดชัดเจน และไม่แจ้งว่าสำเร็จเมื่อเขียนข้อมูลไม่ผ่าน
- เพิ่มการยืนยันก่อนรีเซ็ตหรือเปลี่ยนเวลาระหว่างแข่งขัน
- เพิ่ม validation ใน Firebase Rules และปิดข้อมูลนอก rooms โดยค่าเริ่มต้น

แก้ไขเพิ่มเติมใน stable2
- แก้การกดหยุดเวลาแล้วเดินต่อ จากเดิมที่เวลากลับไปเริ่มจากเวลาเต็ม
- ระบบจะบันทึกเวลาคงเหลือ ณ จังหวะกดหยุด แล้วเดินต่อจากค่านั้นอย่างถูกต้อง
- เพิ่มการจำกัดเวลาคงเหลือไม่ให้มากกว่าระยะเวลาแข่งขันเมื่อ Resume

การยืนยันใน stable3-pause-fix
- หน้า Control แสดงข้อความ stable3 Pause Fix ใต้ชื่อระบบ
- เมื่อกดหยุด ระบบแจ้งเวลาที่บันทึกจริง เช่น "หยุดเวลาไว้ที่ 02:17"
- เมื่อกดเดินต่อ ระบบแจ้งค่าเริ่มต่อ เช่น "เดินเวลาต่อจาก 02:17"

หมายเหตุด้านความปลอดภัย
Rules ที่ให้มาสำหรับการทดสอบหรือใช้งานภายในงานแข่งขัน ผู้ที่ทราบ Room Code
สามารถแก้ข้อมูลได้ หากเปิดใช้งานสาธารณะควรเพิ่ม Firebase Authentication
รหัสผ่าน 2877 เป็นตัวกรองหน้าเว็บแบบง่ายสำหรับงานภายใน ไม่ใช่การยืนยันตัวตน
ระดับเซิร์ฟเวอร์ เพราะ HTML/JavaScript ฝั่งผู้ใช้สามารถถูกเปิดดูซอร์สได้

คำแนะนำวันแข่งขัน
- ใช้ Wi-Fi/LAN เดียวกันที่เสถียร และทดสอบ control + display ก่อนเริ่มงาน
- เปิด control อย่างน้อยหนึ่งเครื่องไว้ตลอดการแข่งขัน
- ห้ามเปิดไฟล์ด้วย file:// โดยดับเบิลคลิก ให้ใช้ Live Server หรือ Static Hosting
